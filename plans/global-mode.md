# 全局模式（等大排列）实施计划

日期：2026-10-31。状态：纯 UI 功能已实现并完成原生窗口验证。上级计划：[Glass 工作空间](glass-workspace.md)。

## 目标与范围

把目前按窗口宽高自动铺满的等大排列，改为固定 16:9、可统一缩放、可纵向滚动的面板网格。产品名称使用「全局模式」；现有代码中的 `grid` 可继续作为内部标识。

本轮设计纯 UI 的全局模式及窗口顶部／底部预留区。不接入 Agent，不增加数据库、网络或磁盘持久化。上下区是窗口级固定组件，在全局模式、主面板全屏、主面板＋侧栏三种模式中持续显示，位置与尺寸不变；各模式只切换中间工作区内容。

## 一、已确认的交互规格

| 项目 | 规则 |
| --- | --- |
| 比例 | 面板整体，包括 Glass，固定为 16:9；Content 的比例由内边距决定，不额外强制 16:9。 |
| 等大 | 同一窗口内的所有面板始终等大，一起缩放。 |
| 最大尺寸 | 按当前窗口可用宽度计算，每行容纳 2 个面板。 |
| 最小尺寸 | 按当前窗口可用宽度计算，每行最多容纳 10 个面板。 |
| 普通滚动 | 上下浏览整个面板网格。 |
| Ctrl＋向上滚动 | 放大面板，每行数量逐步减少。 |
| Ctrl＋向下滚动 | 缩小面板，每行数量逐步增加。 |
| 缩放方式 | 尺寸连续变化，达到容纳下一列的尺寸时自动换行；不是仅在整数列数之间跳档。 |
| 缩放边界 | 到达每行 2 个／10 个对应的尺寸后停止继续放大／缩小。 |
| 关注位置 | 缩放时以鼠标附近的面板为锚点，尽量让它留在视野中。 |
| 选中外观 | 不因选择或聚焦增加描边、外框线或光晕。保留 Glass 材质本身的边缘效果。 |
| 顶部预留区 | 空间顶部保留一个紧凑区块，整合状态与可下拉的提示栏。 |
| 底部预留区 | 空间底部保留一个紧凑区块，放置输入栏，并带有设置图标（setting icon）。 |
| 中间面板区 | 全局网格在顶部与底部之间的剩余区域中排列、滚动和缩放。 |

「每行 2–10 个」限定的是排列容量，不是窗口可拥有的面板总数，也不是要求窗口同时完整显示 2–10 个面板。高度超出窗口时使用纵向滚动。

### 窗口的三个区域

| 区域 | 内容 | 布局职责 |
| --- | --- | --- |
| 上区 | 状态、提示下拉栏 | 固定在空间顶部，保持紧凑；提示可以向下展开。 |
| 中区 | 当前模式的面板工作区 | 占用上下区之间的剩余空间；全局模式承载纵向滚动与 Ctrl＋滚动缩放，其他模式的面板也限制在此區域。 |
| 下区 | 输入栏、设置图标 | 固定在空间底部，输入与设置入口组成同一区块。 |

上下区属于窗口界面，不计入面板数量，不受面板缩放影响，也不随网格滚走；三种模式中均持续显示，尺寸与位置不变。中区不得进入或遮挡上下区。预留区的具体高度、输入栏宽度、材质及设置图标在输入栏内外的位置，留待视觉细化；本计划不把这些数值当成已确认规格。

状态字段、提示内容、输入提交方式与设置项也留待细化。本轮先实现本地 UI 展示与输入编辑，不接回旧 Agent 管理／授权页面，不显示虚假的连接或发送成功状态。

## 二、实施建议与初始默认值

以下默认值已按本次“按照计划完成开发”的授权落实；具体手感仍可在试用时调整：

- 新窗口根据各自窗口的长宽比设定初始列数：横向宽屏每行 4 个，纵向长屏每行 2 个；各窗口独立保存自己的缩放和滚动位置，仅保存在内存中。
- 面板按稳定顺序从左到右、从上到下排列。最后一行从网格左侧开始，空位留空，不拉宽剩余面板。
- 面板少于当前列容量时，仍使用当前缩放尺寸；只有一个面板时也不自动拉伸成整行或主面板。
- 网格整体在水平方向居中，各行使用相同的列位置；不提供水平滚动。
- 全局模式内，普通滚轮优先浏览整个网格，包括鼠标位于 Content 上时。需要滚动内容内部时，进入主面板模式操作；文字输入、点击、选择等内容交互仍保留。
- 主面板与侧栏中的滚动沿用各自行为，Ctrl＋滚动不触发全局网格缩放。
- 双击 Glass 进入主面板时保留全局模式的缩放与滚动位置；返回全局模式时恢复，并确保返回的面板可见。
- 跨窗口移动面板后，面板采用目标窗口的全局尺寸；两个窗口不互相同步缩放。
- 提示下拉栏默认收起，建议点击展开／收起，点击外部或按 Esc 关闭。展开层优先覆盖中区上部，不推动网格重新排列；高度受限，长提示在下拉层内独立滚动。
- 设置图标建议放在输入栏右侧，作为设置入口；具体设置内容另行定义，本轮可先使用纯 UI 占位页。
- 输入草稿先按窗口在内存中保存，缩放、滚动或提示栏开合不能清空草稿。是否跨窗口共享输入，留待后续讨论。

## 三、布局与缩放计算

布局以中区滚动容器的实际可视区域为准，不直接使用整个屏幕尺寸。先从窗口安全区域中扣除顶部预留区、底部预留区及区块间距，再计算面板网格。沿用当前 16 pt 网格外边距与 16 pt 面板间距作为初始值。

```text
中区可视高度 = 窗口安全区域高度 - 顶部区高度 - 底部区高度 - 区块间距
```

所有网格坐标、滚动范围和缩放锚点都使用中区自己的坐标系。上下区高度或全屏安全区域变化时，重新计算中区，并尽量保留关注面板；不能继续用整个窗口高度计算可见行数或滚动边界。

设可视区域宽度为 `V`，左右外边距为 `P`，水平间距为 `G`，可排列宽度为 `A = V - 2P`：

```text
最大宽度 Wmax = (A - G) / 2
最小宽度 Wmin = (A - 9G) / 10
面板宽度 W ∈ [Wmin, Wmax]
面板高度 H = W × 9 / 16
列数 C = clamp(floor((A + G) / (W + G)), 2, 10)
行数 R = ceil(面板数量 / C)
网格高度 = 2P + R × H + max(0, R - 1) × G
滚动文档高度 = max(可视区域高度, 网格高度)
```

- 使用浮点尺寸绘制，列数边界加入稳定的误差处理，避免阈值附近反复换行。
- 缩放保存为归一化参数，由窗口宽度换算实际尺寸；窗口或全屏状态变化时重新计算上下限，不沿用旧屏幕的绝对宽度。
- 面板数量为零时走独立的空状态，不计算虚拟行；内容减少后将滚动位置限制在新的有效范围内。
- 极窄区域中如固定间距会导致最小宽度非正，优先缩减外边距／间距，确保几何有效；不能用负尺寸或悄悄突破 10 列边界。

### 小尺寸下的 Glass 与 Content

目前普通面板的 Glass 边距为 36 pt。缩小到每行 10 个时，不能继续无条件使用固定 36 pt，否则直向屏幕上可能没有剩余 Content 空间。

实施时让全局模式的内边距与圆角随面板尺寸适度缩小，以当前 36 pt 边距作为大尺寸参考，确保外框仍然可见、Content 尺寸始终为正。具体曲线列为可调视觉参数。保持宽边框风格，不在缩小时添加选中线、替换材质或新增第四种展示模式。

全局模式的 Content 继续响应尺寸重新排列，不把整个全局网格改成缩略图截图。侧栏已有的完整画面等比例缩小逻辑保持独立。

## 四、滚轮事件与锚点

### 事件处理

- 只处理事件所属窗口；只有该窗口处于全局模式、鼠标位于中区网格范围内，且未被提示下拉层等覆盖时，才执行全局滚动／缩放规则。
- Ctrl＋滚轮事件由全局模式消费，不能同时传给 Content 或滚动容器，避免一边缩放一边滚动内容。
- 普通滚轮只执行一次纵向网格滚动；不重复转发给嵌套的内容滚动区。
- 统一鼠标滚轮与触控板的增量尺度，限制单次缩放变化，防止一次事件直接跳到另一端。
- 处理触控板的惯性尾段与 Ctrl 中途松开的情况，避免同一手势在缩放和滚动之间意外切换。
- 向上／向下按应用实际收到的滚动语义定义，并在当前 macOS 滚动设置下实测方向。确认 Ctrl 事件能送达 App，不修改用户系统设置。
- 顶部提示层、底部输入栏与设置界面各自处理交互，不把其滚轮事件重复用于网格缩放。输入中的 Enter、空格与文字编辑快捷键不能触发面板放大；提示层打开时，Esc 优先关闭提示层。

### 锚点恢复

缩放前记录鼠标附近面板的稳定 ID、鼠标在面板内的相对位置，以及该位置在可视区域中的纵坐标。计算新尺寸与换行结果后调整纵向滚动位置，尽量恢复该纵坐标。

换行会改变面板横向位置，不能保证面板内同一点在二维空间完全不动；优先保证关注面板不跳出视野。滚动达到顶部／底部时以有效范围为准，不制造额外空白。锚点面板被移走时选择相邻面板，鼠标位于空白区时选择附近的可见面板。

## 六、实施顺序

- [x] 1. **窗口三区与预留入口**：建立固定顶部状态／提示区、中间可滚动面板区及底部输入／设置区；中区使用窗口实际可视高度。
- [x] 2. **固定比例网格**：在中区实现 16:9、2–10 列对应的连续尺寸边界、固定列起点、稳定顺序和有效文档高度。
- [x] 3. **纵向滚动**：接入原生纵向滚动容器，处理空状态、末列与内容减少后的滚动边界。
- [x] 4. **Ctrl＋滚动缩放**：按窗口收到的 Ctrl 滚轮连续缩放，换行时锚定鼠标附近面板并限制上下限；一般滚轮只滚动网格。
- [x] 5. **状态与交互衔接**：完成提示下拉、窗口内输入草稿、设置入口、模式往返、窗口尺寸变化与跨屏移动时的 Content 保留。
- [x] 6. **小尺寸视觉校正**：Glass 边距与圆角随尺寸缩小，Content 始终有正尺寸，并遵守系统减少动态效果设置。
- [x] 7. **验证与试用**：完成几何／事件路由、原生多窗口、全屏及 30 面板滚动验证；封装纯 UI 预览并检查提示、输入与设置画面。

- `scripts/swift-test.sh --filter WorkspaceLayoutTests`：11 项通过、0 失败；另含触控板惯性阶段的 Ctrl 修饰键锁定、滚轮增量限幅及缩放锚点复位。
- `MALTOSE_GUI_TESTS=1 scripts/swift-test.sh --filter WorkspaceNativeTests`：4 项通过、0 失败；覆盖原生全屏、多屏窗口、Content 保留、30 面板滚动及上下区固定。
- `scripts/package.sh` 与 `scripts/package-workspace-preview.sh`：Release build、签章与验证成功。
- 原生 UI 检视确认：状态与提示固定在顶部；输入栏与设置按钮固定在底部；提示可展开；设置入口打开纯 UI 占位页；输入草稿打开设置后仍保留。
- 窗口独立缩放／滚动只保存在内存；未接入 Agent、服务、数据库或磁盘持久化。

试用时仍可调校滚轮灵敏度、缩放锚点的主观感受、提示／输入区高度与小面板玻璃边的视觉；这些是手感微调，不影响目前的几何和事件路由验证。

每一步以可单独检查的结果推进，不把 Agent 接入或其他窗口模式重设计混入本轮。

## 七、验收标准

| 场景 | 必须满足 |
| --- | --- |
| 上下预留区 | 顶部状态／提示栏和底部输入／设置图标始终停留在各自区域；网格滚动和缩放不改变它们的位置或尺寸。 |
| 中区边界 | 网格使用扣除上下区后的可视范围；首行、最后一行及滚动条不被上下区覆盖，原生全屏安全区域下也不重叠。 |
| 提示与输入 | 提示栏可向下展开；输入可以编辑。提示层和输入区域的操作不触发网格缩放或面板放大；网格操作不清空输入草稿。 |
| 设置入口 | 底部有清晰可点击的设置图标，入口可检查；不恢复旧 Agent 接入或授权逻辑。 |
| 比例与等大 | 各尺寸及滚动位置下，面板整体始终为 16:9，同窗口面板尺寸一致。 |
| 两端边界 | 最大尺寸按每行 2 个计算；最小尺寸按每行 10 个计算；反复滚动不能越界。 |
| 多行浏览 | 使用至少 30 个示意面板，可滚到最后一行，Content 不被重建，不出现横向滚动。 |
| 输入路由 | 普通滚动只浏览网格；Ctrl＋滚动只缩放网格；不出现内容、网格同时响应。 |
| 锚点与换行 | 在窗口中部连续缩放、跨列数阈值时，关注面板尽量保持可见，面板顺序不变。 |
| 模式往返 | 放大某面板再返回，全局缩放和滚动位置保留，返回面板可见，笔记等内容状态不丢失。 |
| 多窗口 | 两个窗口可保持不同缩放；拖入的面板使用目标窗口尺寸，取消拖动不改变归属。 |
| 屏幕与极端尺寸 | 横向、直向、超宽屏，以及原生全屏／半透明背景状态切换后，上下限重新计算，尺寸为正，无布局重叠。 |
| 少量与空面板 | 0、1、2、9、10、11、30 个面板均布局正确；最后一行不拉伸，减少数量后无失效滚动位置。 |
| 聚焦外观 | 点击、编辑、双击与键盘聚焦均不为整个面板增加选中描边或光晕。 |

本次交付实现全局模式与三种模式共用的固定上下预留区；纯 UI 预览可用于下一轮视觉手感校正。原生测试验证上下区在三种模式之间保持相同位置与尺寸，且主面板和侧栏内容留在中间工作区。
