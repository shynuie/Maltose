## 預期使用流程

1. 使用者提出需求。簡單問答直接回答；多步工作保存目標、完成條件與小型計畫，麥芽糖在已授權範圍內接續執行。
2. 開發工作交給 Codex，或由使用者在原聊天輸入 `@codex` 直接互動。雙方的追加要求與成果關聯同一任務；直接互動期間，麥芽糖保持既有的真實暫停。
3. 執行結束後，麥芽糖先核對最新要求、實際成果與測試證據。資料不足時清楚標示部分完成、待驗證或需要輸入，不因工具／worker 成功就結案。
4. 資訊輸出層依內容選擇聊天、文檔、圖表、流程圖、圖片或瀏覽器。完整內容留在畫面，語音只說結論、重要限制及需要決定的事。
5. Codex 直接互動收尾時，麥芽糖說明具體成果與缺口，依情境確認下一步；確認前不恢復被暫停的舊工作。一般已授權任務則直接交付，不為每個步驟反覆詢問。

面板規則：新成果預設新增，Agent 有常設權限自主讀取與操作既有面板；遵守人員明確指定的保留要求。既有聊天仍追加訊息，同成果重送仍去重。本地檔案增刪改另沿既有權限。

## 交付順序

1. P0：核對現況，確立任務／結果／呈現合約與測試基準。
2. P1：完整文字與語音摘要分流，接上新文檔結果面板。
3. P2：共同產品任務紀錄、計畫銜接、結果核對與具體的交接收尾。
4. P3：自主面板選擇，對所有 Agent 面板寫入入口落實新增／更新規則。
5. P4：跨程序、重啟、去重、打斷與實際桌面／語音驗收。
6. P5：回歸、封裝、正式切換、回復方式與交付報告。

## 當前接續點與驗收重點

### 每階段的具體交付

| 階段 | 執行內容 | 階段驗收 |
| --- | --- | --- |
| P0 | 先辨認已完成、未提交及尚未驗證的部分，固定任務、成果、呈現三份合約與責任邊界 | 有現況清單、測試基準與遷移／回復方案；保留既有 UI 和使用者資料 |
| P1 | 完整文字與口頭摘要分流，長內容送新文檔；補摘要、詳讀、靜音與打斷 | 同一份長結果可完整閱讀，預設只短講；輸出失敗不重做任務 |
| P2 | 補齊 Main、Python worker 與 Codex 的要求版本、證據核對、接續與收尾 | 多步工作依原授權接續；追加要求不遺失；缺證據不結案；Codex 交回後先確認新意圖 |
| P3 | 根據內容選擇既有面板類型，將新增／更新規則落實到全部 Agent 寫入入口 | 新成果另開面板；明確更新只修改指定面板；模糊目標先釐清；重送不重複開板 |
| P4 | 驗證取消、重啟、斷線、遺失回執、亂序及真實桌面／語音 | 不重做已完成工作、不補播舊答案；各工作區與 30 秒閱讀保護正常；真人驗收另有證據 |
| P5 | 跑當前版本回歸，備份、封裝、切換與核對啟動／退出 | 可回復到舊版；列明版本、修改、實際通過／失敗／未驗證項目，全部必要驗收完成才結案 |

每階段交付可檢視的修改、對應測試與未完成事項。下一階段可以沿用已證實的部分，但不能因局部測試通過就勾選整個階段。已有實作先補驗或修正，不重做。

### 核心工作流範例

使用者提出「研究方案並完成開發」時，麥芽糖保存目標與完成條件，完成研究後依授權委派 Codex；Codex 返回的改動與測試先核對，再決定能否結案或仍需補做。完整分析與成果放入新面板，語音只說結果、重要限制及需要決定的事。

使用者中途輸入 `@codex` 追加要求時，要求納入同一任務的新版本，麥芽糖保持暫停；Codex 完成後，麥芽糖用具體成果與剩餘事項確認接下來的意圖。此確認不等同自動恢復先前暫停的工作。

使用者說「看一下最新股價走勢」時新增圖表；說「更新這張股價圖」且目標明確時才更新原圖。有多張可能目標時先確認；不得依相似標題或目前選取自行取得更新權。

先核對既有未提交修改與分階段證據，沿用背景接續已生成成果的崩潰恢復與過期收尾拒絕，沿用新接的前景成果接納前保存／ACK 恢復，沿用一般前景有界續做與已生成成果恢復，沿用獨立問答後的前景承接，補齊插入問題期間返回的背景成果、未知執行核對、Codex 暫停期間短語音與其餘恢復；沿用已驗證的三方證據核對、每次執行引用、新文檔收尾與持久交付，局部證據不列為整階段完成。再依詳細計畫完成面板規則、故障恢復與正式交付。

- **任務銜接**：追加要求更新版本；舊版本結果不能結束新要求。重啟保留計畫與成果，未知狀態不自動重跑有副作用的工作。
- **成果收尾**：完成、部分完成、待確認有明確區別；修改、測試與剩餘事項有可查證來源。
- **自主呈現**：長文與連結完整可讀；新圖不改舊圖；明確更新只作用於指定目標。Main、Codex 與直接工具遵守相同規則。
- **語音**：一般摘要 1–2 句、約 10–15 秒；可要求詳讀、靜音與打斷；不朗讀長網址、程式碼或整篇結果。
- **可靠性**：重送不重複開板，取消／重啟不補播舊答案；面板或語音失敗仍保留完整成果，不重做原任務。
- **產品回歸**：保留各工作區模式、跨窗口、30 秒手動閱讀保護、身分與資料邊界；正式 App 切換前完成對應版本的回歸與實際驗收。

| 批次 | 具體修改 | 完成條件 |
| --- | --- | --- |
| A：補齊任務承接 | 把背景接續擴到一般前景部分成果／失敗；辨識延續、修改或新任務，保存最新要求與下一步 | 背景與前景皆可在原授權內接續；需要新決策才提問；沒有證據不能結案；已開始但狀態不明的工作不自動重跑 |

| C：統一新增／更新規則 | 先在共用面板操作層實施來源與目標檢查，再接 Main／Codex 與輸出規劃 | 新結果永遠預設新增；明確更新只作用於指定面板；直接工具、重送與外部文字均無繞過入口 |
| D：自主選擇呈現與語音控制 | 完善已接圖表及流程圖、圖片、瀏覽器呈現；增加可保存的語音偏好與完整文字降級 | 主模型可依資料選板；網址／長文／程式碼完整可讀，預設只說 1–2 句；可詳讀、靜音與打斷 |

| F：正式交付 | 跑對應版本全套回歸；備份、封裝、啟動／退出與回復演練 | 有版本、測試／限制及回復紀錄；必要實際驗收通過後再切換正式 App |
